# Street Landing Pages — Design

**Date:** 2026-08-17
**Status:** Approved design, pending spec review
**Author:** Claude (with Niall Murphy)

## Goal

Create 50 dedicated SEO landing pages for individual streets, mirroring the
existing county (`/county/:slug`) and area (`/area/:slug`) pages. The 50 streets
were selected by data analysis (`scripts/analyze_top_streets.py`):

- **30 highest-value streets** — ranked by median sale price, minimum 8
  transactions, apartment complexes excluded.
- **20 highest-volume streets** — ranked by transaction count, apartment
  complexes excluded, deduped against the value list.

Source list: `data/top_streets_analysis.csv`.

## Key decisions (confirmed with user)

1. **Fully static data, baked at build.** Unlike area pages (which live-fetch in
   a `useEffect`), street-page data is pre-generated by a script and baked into
   the SSG build. Zero runtime DB/API calls; the trends chart uses a
   pre-computed series (no `/trends` call). Refreshed by re-running the
   generator after the biweekly PPR sync, then redeploying.
2. **Page depth:** mirror area pages (hero, overview, stats, transactions,
   trends chart) plus a templated FAQ section. Templated text by default, with
   optional hand-written commentary and hero image per street.
3. **URL path:** `/street/:slug` (singular, matching `/county/`, `/area/`).
4. **Single source of truth:** `frontend/src/streets.ts` is authoritative. This
   deliberately avoids the existing drift between `areas.ts`, `vite.config.ts`,
   and `generate_sitemap.py` (which keep separate, diverged area lists).

## Architecture

### Data flow

```
scripts/generate_street_data.py   (run after biweekly PPR sync)
   ├─ reads frontend/src/data/streets_registry.json (slug + normalizedKey)
   ├─ queries Supabase once, per target street key:
   │     aggregate stats + yearly trend series + recent transactions
   └─ writes frontend/src/data/streets/<slug>.json  (one file per street)

vite-react-ssg build → prerenders /street/<slug>/index.html with data inlined
Visitor → static HTML from Vercel CDN. No DB call.
```

`StreetPage.tsx` loads its JSON via an **eager `import.meta.glob('./data/streets/*.json', { eager: true })`**
so data is available synchronously at SSG render time and inlined into the
prerendered HTML (for SEO), not fetched on hydration.

**No backend changes** — `backend/main.py` is untouched.

### Single source of truth

The 50 street entries are hand-authored **once** in a language-neutral JSON,
`frontend/src/data/streets_registry.json` (fields per `StreetConfig` below).
Everything reads from it, so nothing can diverge:

- `frontend/src/streets.ts` imports it and exposes the typed `STREETS` array +
  `streetFromSlug()` (TS consumers: `StreetPage`, `StreetsIndexPage`,
  `vite.config.ts`).
- `scripts/generate_street_data.py` reads it directly (Python) to get each
  street's `slug` + `normalizedKey`.
- `scripts/generate_sitemap.py` reads it (Python) to emit the URLs.

No circular dependency: the registry JSON is authored by hand; the generator
only *consumes* it and writes the per-street data files.

## Components

### `frontend/src/data/streets_registry.json` (new, hand-authored, source of truth)

Array of 50 objects matching `StreetConfig` (below). `streets.ts` imports and
types it; both Python scripts read it directly.

### `frontend/src/streets.ts` (new, typed wrapper)

```ts
export interface StreetConfig {
  slug: string;          // e.g. "ailesbury-road-ballsbridge"
  name: string;          // display street name, e.g. "Ailesbury Road" (St→Street artifacts hand-fixed)
  area: string;          // e.g. "Ballsbridge"
  county: string;        // display county, e.g. "Dublin"
  countySlug: string;    // parent county slug for breadcrumbs/links
  areaSlug?: string;     // link to an existing /area page when one matches
  category: "value" | "volume";
  rank: number;          // rank within its category (1..30 / 1..20)
  normalizedKey: string; // "street|area|county" lowercased — matches generator's street_key
  description: string;   // one-line templated blurb (always present)
  info?: string;         // 2-3 sentence hand-written commentary, where available
  image?: string;        // optional hero photo path under /images (public/)
  imageAlt?: string;     // alt text for the hero photo
}

import registry from "./data/streets_registry.json";
export const STREETS: StreetConfig[] = registry as StreetConfig[];

export function streetFromSlug(slug: string): StreetConfig | undefined;
```

### `frontend/src/data/streets/<slug>.json` (generated)

```jsonc
{
  "slug": "ailesbury-road-ballsbridge",
  "stats": {
    "count": 28, "median": 3875000, "avg": 4281250,
    "min": 1650000, "max": 9500000,
    "firstYear": 2010, "lastYear": 2026
  },
  "trends": [ { "year": 2011, "median": 3200000, "avg": 3400000, "count": 3 }, ... ],
  "transactions": [ // latest ~50, newest first
    { "date": "2026-05-12", "address": "12 Ailesbury Road, Ballsbridge, Dublin 4",
      "price": 4100000, "bedrooms": 6, "propertyType": "Detached", "eircode": "D04..." }
  ],
  "totalTransactions": 28  // true total; table caps at 50
}
```

### `frontend/src/pages/StreetPage.tsx` (new)

Mirrors `AreaPage.tsx`, reusing `PageHeader`, `Breadcrumbs`, `TrendsChart`,
`Footer`, `usePageMeta`, `MapSearchThumb`. No `useEffect` data fetch — data comes
from the imported JSON keyed by slug. Structure:

1. `PageHeader` + `Breadcrumbs` (Home › County › [Area] › Street) with
   `BreadcrumbList` JSON-LD via `usePageMeta`.
2. `<h1>`: "Property Prices on {name}, {area}, {county}".
3. Optional hero `<img>` — rendered only when `config.image` is set.
4. Overview: `config.info` (when present) followed by the always-present
   templated, data-driven paragraph
   (count, median, year range, category context).
5. Stats grid: median, average, transaction count, price range (min–max),
   year range.
6. `TrendsChart` fed the pre-computed `trends` series.
7. Recent-sales table (date, address, price, beds, type) — up to 50 rows;
   footer notes `totalTransactions` if greater.
8. FAQ section (3–4 templated Q&A) with `FAQPage` JSON-LD.
9. `MapSearchThumb` CTA linking to `/?q=<street, area>`.

### `frontend/src/pages/StreetsIndexPage.tsx` (new, `/streets`)

Simple index listing all 50 streets grouped into "Highest-value streets" and
"Most active streets", each linking to its `/street/:slug` page. Ensures the
pages are internally linked, not orphaned. Also linked from relevant County
pages via a "Notable streets" section.

### `scripts/generate_street_data.py` (new)

- Factor the `street_key` extraction out of `analyze_top_streets.py` into a
  shared helper (`scripts/street_key.py`) so analysis and generation cannot
  diverge.
- Read the target `slug`/`normalizedKey`s (the 50 streets) from
  `frontend/src/data/streets_registry.json`.
- Single streaming query over `properties` with the analysis filters
  (`address_normalized IS NOT NULL`, `not_full_market_price = FALSE`,
  `price > 0`, `county IS NOT NULL`).
- Per street: compute stats, per-year trend series, and latest 50 transactions;
  write `<slug>.json`.
- Idempotent (overwrites). Documented as the final optional step after the
  biweekly sync in CLAUDE.md; not auto-wired into `ppr_full_pipeline.py`.

## Routing, SSG & SEO wiring

- **Route:** add `{ path: "/street/:slug", element: <StreetPage /> }` and
  `{ path: "/streets", element: <StreetsIndexPage /> }` in `frontend/src/main.tsx`.
- **Slugs:** `name-area[-county]`; area always included (names repeat, e.g.
  `ailesbury-road-ballsbridge` vs `ailesbury-road-donnybrook`); county appended
  only when needed for uniqueness (`station-walk-rickardstown-kildare`).
- **SSG:** add `STREETS.map(s => '/street/' + s.slug)` and `/streets` to
  `includedRoutes` in `frontend/vite.config.ts` (imported from `./src/streets`).
- **Sitemap:** `scripts/generate_sitemap.py` emits the 50 `/street/<slug>` URLs
  (priority ~0.6) and `/streets`, reading `streets_registry.json` rather than
  hardcoding.
- **Meta:** `usePageMeta` with a unique title/description per street and
  canonical URL.

## Data-quality notes

- **"St → Street" artifact:** the `St→Street` normalization over-expands
  "St Kevin's"/"St Mary's" in `address_normalized` (#20 stored as "Street Kevins
  Park", #28 as "Street Marys Road"). The registry stores hand-corrected display
  names so titles/slugs are clean. **Flag only (not fixed here):** this
  over-expansion likely affects other "St " streets DB-wide.
- A couple of high-volume entries (South Central @ Rockbrook, The Links @ Elm
  Park) are duplex/townhouse developments not caught by the apartment keyword
  filter; retained as legitimate high-search pages.

## Non-goals / YAGNI

- No backend endpoint or DB schema changes.
- No auto-wiring the generator into `ppr_full_pipeline.py` (manual step, documented).
- No per-street hero images at launch — the slot exists; images added later.
- No unifying the pre-existing `areas.ts`/sitemap duplication (out of scope;
  the new page type just avoids adding to it).

## Testing

- Generator: run against the DB, assert 50 JSON files produced, each with
  `stats.count > 0` and `transactions` non-empty; spot-check a known street
  (Ailesbury Road, Ballsbridge) median matches the analysis CSV.
- Frontend: `npm run build` succeeds and prerenders 50 `/street/*/index.html`
  files plus `/streets`; each contains the street name in `<title>` and inlined
  stats in the HTML (SEO check). Smoke-test one page renders stats, chart, table.
- Slug uniqueness: assert no duplicate slugs across the 50.
